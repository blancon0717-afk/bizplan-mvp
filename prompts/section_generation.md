## 후속 인터뷰 질문 가이드 (메모 작성 시 참고용)

아래는 사업계획서 완성도를 높이기 위해 **후속 인터뷰 단계에서 받을 수 있는 질문 목록**입니다.
현재 사용자는 초기 10개 질문에만 답변한 상태이므로, 많은 항목이 비어있을 것입니다.

**사용 방법**:
- 본문에 `llm_inferred`로 채운 부분, 또는 `user_answer`라도 정보가 부족한 부분에 대해
  이 목록에서 관련된 질문을 골라 **`inline_suggestions`의 `note`로 자연스럽게 변환**하세요.
- 이 목록에 없더라도 **사업계획서 완성도에 더 도움이 된다고 판단되는 꼬리질문**은 자유롭게 생성 가능합니다.
- 목록의 질문을 그대로 복사하지 말고, **본문 맥락에 맞게 재작성**하세요.

## 작성 지시

위의 요구사항과 Skills를 적용하여, 사용자 답변 기반으로 **{section_title}** 섹션을 작성하세요.

특별 주의:
1. 답변이 없거나 부족해도 반드시 초안을 작성하되, 아래 두 가지만을 기반으로 추론하세요:
   ① 사용자가 입력한 아이템/서비스명과 설명
   ② 다른 질문에서 충실하게 답변된 내용

   절대 금지:
   - 다른 업종, 다른 아이템, 다른 서비스 내용 임의 삽입
   - 아이템과 무관한 일반적인 내용으로 채우는 것 (예: 아이템이 'AI 사업계획서 솔루션'인데 '일정관리, 이메일 자동분류' 같은 엉뚱한 기능을 추론하는 것)
   - 아이템명조차 언급하지 않고 추상적으로만 작성하는 것

   추론 부분은 반드시 severity=critical 인라인 메모로 'AI 추론 내용입니다. 실제 정보로 교체해주세요'를 달아주세요.
   **content_segments를 빈 배열로 반환하는 것은 절대 금지입니다.**
2. 수치 및 출처 처리 규칙: `[출처 필요]` `[추정값]` `[수치 필요]` 태그를 본문에 절대 삽입하지 말 것. 상세 규칙은 `skills/L1_universal/U01_numbers_with_sources.md` 참조.
3. 해당 섹션 분량은 A4 기준 0.5~1.5페이지가 적절합니다 (양식 전체 분량 고려).
4. **inline_suggestions anchor_text 작성 규칙 (절대 준수)**:
   - anchor_text는 반드시 위에서 작성한 content_segments의 text 안에 **글자 하나도 다르지 않게 그대로 존재하는 문구**여야 함
   - 본문에 없는 문구, 요약한 문구, 비슷하지만 다른 문구 절대 금지
   - anchor_text 길이는 10~25자 이내로 제한. 너무 짧으면(5자 이하) 매칭 오류 발생하므로 금지
   - anchor_text는 해당 note(피드백 내용)와 직접 관련된 문장에서 추출할 것. 제목(■로 시작하는 줄)에서 추출 금지
   - anchor_text 선정 순서: ① 피드백 대상 수치/키워드가 포함된 문장 → ② 해당 내용이 서술된 문장 → ③ 관련 단락의 첫 문장
   - 작성 완료 후 self-check: 각 anchor_text를 content_segments 전체 텍스트에서 검색했을 때 정확히 일치하는 문구가 있는지 확인 후 반환
5. **추진 일정표 날짜 작성 규칙 (절대 준수)**:
   - 추진 일정표의 "추진 기간" 컬럼은 반드시 구체적인 날짜 또는 기간으로 채울 것. 공란 절대 금지.
   - 사용자가 인터뷰에서 일정을 언급했으면 그 내용을 반영
   - 언급이 없으면 사업계획서 작성 시점을 기준으로 단계별 소요기간을 합리적으로 추론하여 작성
   - 예시: 1단계(2026.05~2026.07), 2단계(2026.07~2026.09) 형태로 작성
   - 모든 단계가 동일한 기간으로 뭉뚱그려지는 것 금지. 각 단계별 특성에 맞게 다른 기간 설정
   - 협약기간이 명시된 경우 그 범위 안에서 단계별로 배분
6. **출처 표기 규칙 (절대 준수)**:
   - 출처는 외부 데이터(통계청, 시장조사기관, 논문, 뉴스 등)를 인용할 때만 표기
   - "출처: 자체 사업 계획", "출처: 자체 개발 일정", "출처: 자체 경쟁사 분석", "출처: 자체 집계" 등 자사가 직접 작성한 것을 출처로 표기하는 것 절대 금지. 출처가 없는 수치는 "(추정)" 또는 "(업계 평균 기준)"으로 표기하거나 llm_inferred 세그먼트로 분류할 것.
   - 자체적으로 작성하거나 추론한 내용에는 출처를 달지 말 것
   - 외부 출처가 없는 내용은 출처 없이 서술하면 됨
7. **사업비 계산 규칙 (절대 준수)**:
   - 정부지원사업비(정부지원금)가 전체 사업비의 일부 비율임을 반드시 인지할 것
   - 예: 정부지원금 1억원이 70% 비율이면 → 총사업비 = 1억원 ÷ 0.7 = 약 1억 4,286만원
   - 절대 금지: 총사업비 = 정부지원금으로 계산하는 것
   - 사업비 집행계획 표에서 정부지원사업비(ⓐ) + 자기부담사업비(ⓑ) = 총사업비가 되도록 작성
   - 각 사업의 yaml instructions에 명시된 비율 예시를 반드시 참고하여 계산할 것
8. **사업비 표 서식 규칙 (절대 준수)**:
   - 사업비 집행계획 표의 컬럼은 반드시 "비목 | 집행 계획 | 정부지원사업비(원) | 자기부담사업비(현금) | 자기부담사업비(현물) | 합계" 형태로만 작성. "집행기간" 컬럼 절대 포함 금지.
9. **시장규모 작성 규칙 (절대 준수)**:
   - TAM(전체시장) → SAM(유효시장) → SOM(수익가능시장) 3단계로 반드시 분해할 것. SOM은 반드시 "타깃 고객 수 × 단가 × 점유율 가정"으로 산출 근거를 명시할 것.
10. **섹션별 필수 포함 항목 (절대 준수)**:
   - Solution 카테고리 섹션: TAM→SAM→SOM 시장규모 분해 반드시 포함. BEP(손익분기점) 산출 포함.
   - Scale-up 카테고리 섹션: BEP 산출 (월 고정비 ÷ 건당 마진 = BEP 판매량 공식 사용). TAM→SAM→SOM 포함.
   - Team 카테고리 섹션: 시각자료 플레이스홀더 표 반드시 포함 (팀 구성도 또는 협력사 네트워크 시각화).
   - 위 항목이 answers_block에 정보가 없으면 llm_inferred로 추론하여 반드시 포함할 것.
