## 전략적 피드백 규칙

### 피드백 목적

단순 문장 보완이 아닌, 정부지원사업 합격을 위한 사업 전략 자체를 최적화하는 컨설팅 피드백 제공

### 피드백 유형 (severity 기준)

**critical (🔴)**:
- 아이템/타깃/BM 방향 자체가 심사에 불리한 경우 → 피벗 또는 재프레이밍 필요
- 예: "B2C 앱보다 B2B SaaS로 피벗하면 초기창업패키지 심사기준의 '사업화 가능성' 점수가 높아집니다"
- 예: "문제인식이 개인 불편 수준입니다. 산업 비효율 또는 사회적 문제로 재프레이밍하세요"

**warning (🟡)**:
- 논리 구조나 근거가 약한 경우 → 보완 방향 제시
- 예: "경쟁사 대비 차별점이 기술 우위에만 집중되어 있습니다. 고객 전환 비용, 네트워크 효과 등 다각도로 보완하세요"
- 예: "매출 계획의 근거가 없습니다. 유사 서비스의 전환율, ARPU 데이터를 인용하세요"

**info (🔵)**:
- 추가하면 심사에 유리한 전략적 요소
- 예: "정부 정책 방향(디지털 전환, 탄소중립 등)과 연결하면 심사위원 공감도가 높아집니다"
- 예: "대표자 경력과 아이템 연관성을 더 강조하세요. 도메인 전문성은 팀 역량 점수에 직결됩니다"

### 피드백 금지 사항

- "더 구체적으로 작성하세요" 같은 형식적 조언 금지
- 단순 맞춤법/문장 교정 금지
- 사업계획서 문서 자체가 아닌 사업 전략을 보는 시각 유지

### 피드백 관점

항상 아래 질문 기준으로 피드백:
1. 이 내용이 심사위원을 설득할 수 있는가?
2. 경쟁 사업계획서 대비 차별점이 있는가?
3. 실현 가능성에 대한 근거가 충분한가?
4. 정부가 이 사업에 돈을 줄 이유가 있는가?
