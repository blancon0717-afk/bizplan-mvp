# 사업계획서 자동 피드백 솔루션 — 설계 기초 자료

> **용도**: 작성된 사업계획서를 입력받아 심사위원 수준의 피드백을 자동 도출하는 시스템의 설계 레퍼런스.
> 회귀분석 루브릭 + 심사위원 실제 피드백 데이터 + 아이템 키워드 전략을 통합한 근거 기반 피드백 엔진.

---

## 1. 솔루션 개요

### 입출력

| 구분 | 내용 |
|---|---|
| **입력** | 사업계획서 전문 텍스트 (PDF 추출 또는 직접 입력) + 지원 프로그램명 |
| **출력** | ① 루브릭 점수 (합격 가능성 예측) ② 카테고리별 피드백 문장 ③ 강화 우선순위 리스트 |

### 핵심 원칙

1. **근거 기반**: 추상적 코멘트 금지. 모든 피드백은 루브릭 통계 가중치 또는 실제 심사위원 발언에서 파생.
2. **이중 레이어**: 공통 피드백(완성형 체크리스트) + 프로그램 특화 피드백.
3. **1:1 유사도 학습**: 기존 합격/불합격 사업계획서와 심사위원 피드백 쌍을 few-shot 예시로 제공.

## 3. 피드백 생성 로직 (3단계)

### 단계 1 — 루브릭 스코어링 (정량)

사업계획서 텍스트에서 피처 존재 여부/수치를 추출해 점수화.

**유의미 피처 (합격 신호 +)**

| 피처 | 배점 | 감지 방법 |
|---|:--:|---|
| 누적 투자 | 5pt | 투자금액·투자사 언급 감지 |
| 필수 재료 공급처 네트워크 보유 | 5pt | 공급처·협력사·MOU 언급 |
| 제조 전문 인력 (기술자) 보유 | 4pt | 팀 구성 섹션 기술자 역할 감지 |
| 소재지+주관기관 일치 | 4pt | 주소·기관명 비교 |
| MOU 보유 개수 | 3pt | MOU 등장 횟수 카운트 |
| 투자의향서 확보 | 3pt | 투자의향서 언급 감지 |

**유의미 피처 (반직관적 신호 −)**

| 피처 | 배점 | 해석 |
|---|:--:|---|
| FGI(포커스그룹인터뷰) | -5pt | 기술 중심 프로그램에서 시장조사 과잉이 감점 패턴 |
| 비즈니스 모델 다양화 | -4pt | 수익원 분산 = 집중력 부족으로 읽힘 |
| 실제 실험 사진 보유 | -3pt | 초기단계 아이템 신호 가능성 |
| 아이템 관련 경력 증빙 | -3pt | 이력서 중심 계획서에 패널티 패턴 |

> 반직관 피처는 프로그램 유형 확인 후 적용. 예창/초창(기술형)에서 주로 작동.

**잠정 피처 (보조 +1~2pt)**
- `+`: 견적서, 수요처 확보, R&D 인력, SW 개발인력, 고용, 자체 생산시설, 직전 수출
- `−`: 디자인 네트워크, 영업마케팅 인력, 디자인 인력, 수상이력

---

### 단계 2 — 카테고리 피드백 생성 (정성, LLM)

`feedback_skill.md` 공통 레이어의 16개 카테고리를 LLM 평가 축으로 사용.

| 카테고리 | 빈도 | LLM 지시문 핵심 |
|---|--:|---|
| 시장/고객 | 26건 | 타깃 고객과 시장 규모를 TAM/SAM/SOM 관점에서 평가 |
| 차별성/경쟁사분석 | 21건 | 기존 대안 대비 핵심 차별점과 경쟁사 분석 충분성 평가 |
| 진입장벽/보안 | 17건 | 모방 방지 메커니즘과 기술적 해자 구체성 평가 |
| 마케팅/영업/수익창출 | 15건 | 초기 고객 확보 채널과 수익 경로 실현가능성 평가 |
| 아이템 설명 | 14건 | 핵심 기능과 가치 제안이 한 문장으로 명확한지 평가 |
| 비즈니스모델 | 10건 | 수익 구조와 단위 경제학(LTV/CAC) 구체성 평가 |
| 문제인식 | 7건 | 문제 규모·심각도가 정량화되어 있는지 평가 |
| 기술부족 | 4건 | 기술적 우위 근거(특허·논문·실험결과) 존재 여부 평가 |

---

### 단계 3 — Few-shot 예시 주입 (RAG)

`data/feedback_pairs.json`에서 아래 기준으로 유사 피드백 3~5건 검색해 LLM 컨텍스트에 삽입.

**검색 기준 (우선순위 순)**
1. 같은 `사업명` (프로그램 일치)
2. 유사 산업군 키워드 (아이템 설명 유사도)
3. 같은 `태그` (피드백 유형 일치)

**프롬프트 구조**

```
[시스템 지시]
너는 창업 지원 사업 서류 심사위원이다.
아래 실제 심사위원 피드백 예시를 참고해 주어진 사업계획서를 평가하라.
피드백은 구체적 근거를 포함하고, 개선 방향을 제시하라.

[Few-shot 예시]
기업: {기업명} / 아이템: {아이템명} / 프로그램: {사업명}
태그: {태그}
심사위원 피드백: "{피드백}"

(3~5건 반복)

[평가 대상]
{사업계획서 텍스트}

[출력 형식]
카테고리별 피드백 + 점수 + 보강 방향
```

## 4. 피드백 리포트 출력 구조

```markdown
# 사업계획서 피드백 리포트

## 종합 점수
- 루브릭 점수: XX / 35점 (유의미 피처 기준)
- 합격 가능성: 상 / 중 / 하

## 강점 (보유 피처)
- ✅ [피처명] — [근거 문장]

## 보강 필요 항목 (빈도순)
1. [카테고리] [피드백] — 유사 기업 심사위원 코멘트 참조
2. ...

## 아이템 전략 체크
- 합격 키워드 클러스터 해당 여부
- 제목 패턴 점검 (A~E)

## 프로그램 특화 주의사항
- [선택 프로그램] 전용 피드백 (feedback_skill.md 레이어 2)
```

## 6. 파일 연결도

```
입력: 사업계획서 텍스트 + 프로그램명
        │
        ├─► 루브릭 스코어링
        │     └─ data/rubric_all_clean.json → 점수 + 피처 목록
        │
        ├─► 카테고리 피드백 생성 (LLM)
        │     ├─ reports/feedback_skill.md → 공통 평가 축
        │     └─ data/feedback_pairs.json → few-shot 예시
        │
        └─► 아이템 전략 점검
              └─ reports/item_keyword_strategy.md → 키워드/제목 패턴

출력: 피드백 리포트 (점수 + 카테고리 피드백 + 우선순위)
```
